Comparative implementation ingest checklist

Use when an external repo, framework, or methodology must be added to the PKM and compared against the local system.

Artifact checklist

- raw capture with fetch method and inspected evidence
- source page with relevance and boundaries
- implementation page when the source is an actual system
- analysis page when the user asks for comparison

Evidence to capture for repos

- README positioning
- observed folder and script layout
- concrete commands that can verify the project is real and runnable
- result of at least one verification step when available

Comparison axes

- core abstraction
- semantic depth vs operational governance
- raw/curated/compiled knowledge layers
- maintenance model: health, dedup, repair, decay, resurfacing
- runtime portability and model agnosticism
- worldview-specific vs generic vault applicability

Decision rule

If the system is operationally strong but semantically shallow, record it as complementary rather than as a replacement for ontology-first architecture.

Indexing surfaces to update

- index
- log
- connection-map
- glossary only for genuinely reusable new vocabulary
