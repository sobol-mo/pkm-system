Pattern: social post plus attached infographic or screenshot

When to use

Use when the source text is only part of the payload and attached images carry examples, taxonomy items, or operational detail.

What to do

- model the post and image as one multimodal source unless they are clearly separate publications
- capture text preview or transcript
- extract image-only facts separately
- state explicitly why the source belongs in the PKM: terminology, checklist, taxonomy, ethics framing, etc.
- connect the source to nearby existing concepts instead of recreating them all from scratch

Good output shape

- raw note with source text and image-only additions
- source page with summary, value, and graph links
- concept pages only for stable reusable nodes
- updates to index, glossary, connection map, or log if the PKM uses those structures

Lesson from session

A compact social post about AI can still be worth ingesting when the attached visual supplies the real operational taxonomy. The image may contain the reusable examples and component list that make the source valuable for systems design, ethics analysis, or gap assessment.

Anti-patterns

- ingest only the text and lose the infographic payload
- flatten the source into abstract notes with no trace of which details came from the image
- create excessive concept-page sprawl when the source is mainly a checklist or taxonomy
